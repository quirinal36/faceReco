# P0 공개 생체정보 노출 대응: 조율 및 승인 체크리스트

이 문서는 #21의 코드 변경 이후, 담당자가 결정하거나 외부와 조율해야 하는
작업을 한곳에 모은 체크리스트입니다. 체크하거나 아래의 **응답 양식**을 복사해
답변해 주세요.

> 중요: 이 문서나 답변에 실제 얼굴 이미지, 이름·출석 정보, Bearer token,
> 비밀 파일 내용, 관리자 개인 연락처를 넣지 마세요. 필요하면 비공개 승인 채널과
> 내부 사건 번호만 사용하세요.

현재 코드 변경은 로컬 작업 트리에만 있으며, 커밋·푸시·Git 이력 재작성·GitHub
이슈 수정은 아직 수행하지 않았습니다.

## 1. 공개 Git 이력 사고 대응

- `2b84ac8`
- `4903888`
- `31d1ae0`

- [ ] 이 노출을 개인정보/생체정보 보안 사고로 공식 분류한다.
- [ ] 비공개 사건 번호 또는 담당 팀을 지정했다: `________________`.
- [ ] 법무·개인정보보호·보안 담당자에게 검토를 요청했다.
- [ ] 영향을 받을 수 있는 사람, 국가/관할, 동의·통지·신고 의무를 내부 절차로
  확인했다.
- [ ] 현재 브랜치의 코드 수정본을 먼저 커밋해 보존해도 된다.
- [ ] 모든 공개 참조의 이력 재작성과 force-push를 승인한다.
  - 대상: 기본 브랜치, 태그, 열려 있는 PR/MR의 head, release/package/CI artifact
  - 영향: 기존 clone은 다시 clone하거나 강제 동기화해야 하며, 열린 PR의 commit

- [ ] force-push 전에 영향을 받는 협업자에게 유지보수 시간과 재동기화 방법을
  공지한다.
- [ ] 원격 저장소 관리자 권한을 가진 담당자가 정해졌다: `________________`.

이력 재작성은 파괴적 작업입니다. 명시적으로 승인받기 전에는 실행하지 않습니다.
승인 후에도 원본을 일반 디스크나 티켓에 복사하지 않고, 승인된 비공개 증거 보존
절차를 따릅니다.

## 2. GitHub·fork·캐시·artifact 정리

이력 재작성만으로 GitHub의 캐시, fork, PR 첨부물, Actions artifact, 릴리스 자산,
검색 색인, 다운스트림 clone에서 이미 복제된 데이터가 자동으로 사라지지 않습니다.

- [ ] 공개 fork와 네트워크 그래프의 복제본을 확인할 권한/담당자를 지정했다.
- [ ] 공개 PR/MR, issue 첨부물, release 자산, Actions artifact, Pages/패키지
  배포물을 점검한다.
- [ ] GitHub Support 또는 조직의 GitHub 보안 연락처에 cache/commit object 제거
  요청을 보낼 수 있다.
- [ ] 외부 fork 소유자 및 다운스트림 사용자에게 연락·삭제 요청을 할 법적/조직적
  권한과 문구를 검토했다.
- [ ] 원본 blob이 검색 결과·CDN·브라우저 캐시에 남을 수 있음을 사고 기록에
  반영했다.

## 3. 운영 Edge 배포 승인

코드는 운영에서 loopback 바인딩, 파일 기반 비밀, 암호화 저장소 확인,
사전 배포 모델을 요구합니다. 실제 방화벽·네트워크·디스크 암호화는 이 저장소가
대신 설정할 수 없습니다.

- [ ] 운영 Edge의 소유자와 호스트/장치 식별자를 비공개 운영 문서에 기록했다.
- [ ] API는 `127.0.0.1` 또는 Unix domain socket만 수신하며, 공유기 포트 포워딩,
  공인 load balancer, 공인 IP 수신이 없음을 확인했다.
- [ ] host firewall과 서비스 설정에서 외부 inbound 연결을 차단했다.
- [ ] Edge의 outbound는 승인된 Edu Manager 정확한 HTTPS host의 TCP 443만 허용한다.
- [ ] 운영 모델은 staging/build 환경에서 검증한 뒤 로컬에 사전 배치했으며, 운영
  런타임의 일반 인터넷 접근은 차단했다.
- [ ] `backend/data`, SQLite WAL/journal, export, backup, swap/hibernation이 같은
  LUKS2 또는 BitLocker 암호화 경계에 있음을 확인했다.
- [ ] 전용 서비스 계정, POSIX `0700`/`0600` 또는 동등한 Windows ACL을 적용했다.
- [ ] `FACERECO_ENCRYPTED_STORAGE_VERIFIED=true`를 실제 확인 후에만 설정한다.

## 4. 프록시·브라우저 경계

- [ ] 프록시가 없음: 브라우저와 API가 같은 장치의 loopback에서 통신한다.
  또는
- [ ] 프록시가 있음: 프록시가 loopback/UDS로만 API에 연결하고, 외부 TLS 종단과
  접근 제어는 별도 보안 경계에서 적용한다.
- [ ] 프록시·WAF·보안 에이전트의 요청 body buffering을 비활성화했다. 비활성화할 수
  없다면 해당 임시 경로도 검증된 암호화 볼륨과 전용 ACL로 보호한다.
- [ ] 배포 UI origin을 정확히 확정했고 `FACERECO_CORS_ORIGINS`에 scheme·host·port를
  포함해 설정했다. `*`, `null`, URL path는 사용하지 않는다.
- [ ] 프록시 access log, APM, error tracker, browser telemetry가 Authorization header,
  query string, request body, 얼굴 이미지, 이름을 기록하지 않음을 확인했다.

## 5. 비밀·운영자·Device 준비

- [ ] 운영용 operator/device token은 서로 다른 32자 이상 난수다.
- [ ] 운영에서는 `FACERECO_OPERATOR_TOKEN_FILE`과
  `FACERECO_DEVICE_TOKEN_FILE`만 사용한다. 값 자체는 이 문서나 채팅에 공유하지
  않는다.
- [ ] 비밀 파일은 전용 서비스 계정 소유이며 POSIX `0600` 또는 동등한 ACL이다.
- [ ] Edu Manager outbound credential은 로컬 API token과 분리되어 있다.
- [ ] token 회전 책임자, 배포 방법, 긴급 폐기 절차를 정했다.
- [ ] P0 설계가 단일 local device principal만 지원한다는 제약을 수용했다. 여러
  kiosk/device를 운영하려면 Edu Manager 연동 전 다중 device subject 설계를 추가한다.

## 6. 보존·삭제·백업

- [ ] 원본 등록 frame은 보관하지 않고, 필요한 경우에만 제한된 얼굴 썸네일을
  보관한다는 제품 정책을 승인했다.
- [ ] 얼굴 메타데이터·임베딩·썸네일·출석·export·backup별 보존 기간을 정했다.
- [ ] 암호화된 backup 대상, 복구 책임자, 정기 복구 시험 일정을 정했다.
- [ ] 삭제 요청 시 운영 데이터·export·backup·Edu Manager로의 삭제 전파 방법을
  정했다.
