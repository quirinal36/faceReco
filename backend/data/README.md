# 비공개 생체정보 데이터 디렉터리

이 디렉터리는 FaceReco 런타임의 제한 생체정보와 개인정보를 저장합니다.
얼굴 이미지·썸네일, 임베딩, 얼굴 메타데이터, 이름, 출석 SQLite 및 그 백업은
모두 공개하면 안 되는 데이터입니다. 자세한 운영 기준은
[보안 및 개인정보 운영 가이드](../../docs/SECURITY.md)를 참고하세요.

## 디렉토리 구조

```
data/
├── face_database.json     # 얼굴 메타데이터와 내부 저장소 상대 경로
├── attendance.db          # 이름과 출석 기록을 포함한 SQLite
├── embeddings/            # 얼굴 임베딩 벡터 (.npy, 512차원)
│   └── person_*.npy
└── faces/                 # 제한된 얼굴 썸네일(여전히 생체정보)
    └── person_*.jpg
```

SQLite의 `-wal`, `-shm`, 저널, 임시 파일과 내보내기 파일도 동일하게
보호해야 합니다. 실제 파일명은 구현에 따라 달라질 수 있습니다.

## 필수 운영 기준

- `/data` 정적 URL로 이 디렉터리를 제공하거나 웹 서버 document root에 두지
  마세요. 저장 경로나 `image_path`를 API 응답에 노출하지 않습니다. 필요한
  썸네일만 operator Bearer 인증이 필요한 전용 API로 요청합니다.
- `.gitignore`는 새 파일의 실수만 줄이며 이미 커밋된 데이터, Git 기록, fork,
  CI artifact 또는 screenshot을 삭제하지 않습니다. 실제 생체정보가 Git에
  들어갔다면 보안 사고로 처리합니다.
- POSIX에서는 전용 서비스 계정이 소유하도록 하고 디렉터리는 `0700`, 모든
  데이터·SQLite·저널·백업 파일은 `0600`, 프로세스 `umask`는 `077`로
  유지합니다. symlink를 사용하지 않습니다.
- Windows에서는 전용 NTFS 서비스 계정만 필요한 권한을 갖도록 ACL 상속과
  광범위한 `Users` 권한을 제거합니다. 공유 폴더나 동기화 폴더에 저장하지
  않습니다.
- 운영 환경의 이 경로, SQLite 임시 파일, swap/hibernation 및 로컬 백업은
  LUKS2 또는 BitLocker 암호화 볼륨에 있어야 합니다.
- 원본 등록 업로드를 별도 보관하지 마세요. 제품에 필요한 제한 크기
  썸네일도 원본과 같은 생체정보 등급으로 취급합니다.

## 생성 및 접근

파일은 FaceReco 서비스가 필요할 때 생성합니다. 애플리케이션 외부에서 직접
열람·수정하지 말고, 역할이 제한된 API와 승인된 관리 절차만 사용하세요.
운영자용 token과 단일 로컬 device token은 별도 비밀 저장소에 두며 이
디렉터리나 데이터 백업에 포함하지 않습니다.

## 백업, 복원 및 삭제

일반 `tar`/ZIP으로 평문 백업하지 마세요. 애플리케이션 쓰기를 중지하거나
SQLite 일관성이 보장되는 snapshot을 만든 뒤 승인된 암호화 백업 도구와
대상만 사용하고, 무결성·보존 기간·삭제 전파를 기록합니다. 복원은 격리된
암호화 호스트에서 권한과 DB 일관성을 확인하며 시험합니다. 개인 삭제 요청은
메타데이터, 모든 임베딩, 썸네일, 허용되는 범위의 출석, 내보내기, backup
사본까지 보존 정책에 따라 처리해야 합니다. SSD 파일 하나를 덮어쓰는 것은
안전한 삭제를 보장하지 않으므로 폐기 시 암호화 키 폐기 또는 승인된 매체
폐기 절차를 사용합니다.
